# Kama 现金超级送：需求与交互原型计划

- 状态：已批准
- 版本：v1
- 更新日期：2026-11-24
- 批准记录：用户明确回复“执行”，批准本计划 v1。
- 交付记录：HTML 及 PRD 已生成，业务与隔离 DOM 检查通过；浏览器视觉验收受安全策略阻止，详见 verification.md，不记为完整验收通过。
- 依据：已逐项确认的《Kama现金超级送活动需求.md》及 Kama 整站 PRD。冲突时，以本次对话中最新确认的规则为准。

## 1. 目标与交付

将已确认的现金超级送规则整理为需求文档及可直接打开的静态交互原型，覆盖开红包、邀请注册、任务助力、达标领取与后台配置。

- `index.html`：统一原型入口，可切换发起人端、好友端、运营后台。
- `prd.html`：独立需求文档，包含范围、流程、功能、规则、异常与验收标准。
- `styles.css`、`app.js`：原生样式与交互，不依赖外部 CDN、框架或真实接口。
- 审阅布局：左侧可交互原型，右侧对应规则；统一使用 R-xxx 编号，支持双向定位。
- 中文审阅文案；金额使用印度卢比。演示金额、次数、日期、上线时间明确标记为演示数据，不代表正式配置。

## 2. 用户与终端

- 发起人：全平台新老用户；手机 App 页面，约 390px 宽的审阅视口。
- 好友：通过邀请链接进入的用户；移动端分享落地、模拟注册及任务助力页面。
- 后台：桌面端活动管理，使用现有 Kama 后台角色权限，不新增角色或财务权限。
- 保留现有首页、钱包及导航结构；与本次无关的功能置灰、不可触发，并注明实际产品仍按现状运行。

## 3. 页面范围及核心流程

| 区域 | 页面或模块 | 主要交互 |
| --- | --- | --- |
| 发起人 | 首页活动常驻入口、自动弹窗 | 进入、关闭、再次进入；模拟重新打开 App 或返回首页 |
| 发起人 | 未开红包、红包详情、活动规则 | 开包、查看初始进度与差额、倒计时、查看助力明细 |
| 发起人 | 邀请分享 | 分享内容、复制链接、WhatsApp 分享预览；不实际发送消息 |
| 发起人 | 达标领取、处理中、到账或异常结果 | 领取、禁止重复提交、查看个人钱包与活动记录 |
| 好友 | 邀请落地、模拟注册、注册助力结果 | 绑定邀请来源、注册成功后自动助力、查看实际金额 |
| 好友 | 指定任务与助力记录 | 模拟提交、成功回传、失败回传、重复完成、达到次数上限 |
| 后台 | 活动列表、配置编辑 | 查看活动，编辑金额、时限、任务、次数、弹窗间隔及档期 |
| 后台 | 参与、助力、发奖记录及效果统计 | 筛选、查看明细，区分任务助力人数与次数、发奖与到账 |

主流程：发起人开包 → 分享 → 新好友注册自动助力 → 好友完成指定任务并有效回传助力 → 红包达标 → 发起人领取 → 个人钱包到账。

## 4. 关键规则

1. 一期后台活动即一个任务周期；每账号每期一个红包，无档位、无重开。活动开启后全平台可参与，无预算、预占或参与名额限制。
2. 初始金额、目标金额、注册助力金额、任务助力金额由后台配置；初始金额仅为活动进度。
3. 只有功能上线后、通过邀请链接在本期新邀请注册并绑定该发起人的好友可以贡献助力。上线前用户可开红包，但不能贡献助力。
4. 每位好友本期注册助力一次，注册成功自动计入；任务助力支持多次，每位好友的次数上限后台配置。同一指定任务不同有效完成记录可重复贡献，同一记录重复回传不重复计次。
5. 新一期必须邀请新好友；之前期次的好友不能为新一期贡献两类助力，助力不得转给其他发起人。
6. 仅指定推广任务的有效成功回传计入助力；点击、领取、提交及失败回传不计入。两类助力均只补足差额。
7. 默认开包后 24 小时为助力期；领取截止为助力截止后 72 小时，两项时长后台配置。提前达标立即可领，不从达标时重新起算领取截止。
8. 助力截止未达标即失效；截止后的任务成功回传不补计，不设等待期。整体活动结束停止新开包，已开包保留个人完整时限。
9. 红包达标、失效或领取后停止接收助力；原分享链接仍保留注册入口，并展示对应状态。
10. 领取完整目标金额至 Kama 个人钱包，提现沿用现有规则。领取申请与到账分开展示，钱包异常核对原单，不重复发奖。
11. 弹窗间隔后台配置，单位分钟；上次实际弹出后计时，满足间隔后在下次打开 App 或返回首页时检查触发。停留页面不会到点强制弹出。
12. 领取成功或失效后本期停止自动弹窗，首页入口仍可查记录；主动进入不受自动弹窗间隔限制。
13. 时间显示沿用 Kama 整站 PRD 的 Asia/Kolkata；截止及助力判定以服务端时间为准。上线分界时间正式值待实施填写，原型可用演示时间验证资格。

## 5. 配置、状态与异常

- 编辑表单包含活动名称、活动起止时间、四项金额、指定任务、每位好友任务助力次数、助力小时数、领取小时数、弹窗间隔分钟数。
- 演示表单必填项需完整；金额最多两位小数，0 ≤ 初始金额 < 目标金额，两类助力金额为正数；次数及小时、分钟间隔为正整数；开始时间早于结束时间，至少指定一个任务。正式参数值不预设为业务承诺。
- 不提供预算、预占、名额、多档配置或回传等待期字段。
- 原型提供演示控制区，用于切换时间、好友身份、周期及回传事件；不在实际产品界面混入测试按钮。
- 可查看未开包、无助力记录、助力中、达标待领取、领取处理中、已到账、异常待核对、助力失效、领取过期状态。
- 好友异常包含上线前账号、此前周期好友、归属他人、助力已记录、任务失败、次数已满、红包已结束、截止后回传。
- 网络失败提供明确提示及重试；重复点击、重复回传不得重复助力或发奖，确认状态不清楚时保留原单核对。
- 进行中红包保留登记时的金额、次数与个人期限，后台修改后不回写已产生流水。

## 6. 规则标注与改动分类

- 首页现有结构、钱包提现及非活动功能标为“现有保留”，本次新增活动入口及规则标为“新增”，由 Uono 原型调整的助力与领取机制标为“修改”。
- 原型、右侧规则卡、PRD 使用一致功能名称、改动分类及稳定 R-xxx 编号。
- 点击左侧规则标记定位右侧卡片；点击右侧卡片定位并高亮对应原型元素；跨场景时切换到对应页面。

## 7. 验收标准

1. 双击 `index.html` 和 `prd.html` 均可打开；断网可查看核心页面并完成模拟交互。
2. 首页开包、分享、新好友注册、同任务多次有效回传、达标领取与钱包到账可完整演示。
3. 后台可修改演示配置并在新参与流程中验证；无预算、名额、多档或回传等待字段。
4. 可验证注册助力一次、任务助力上限、重复回传去重、新周期须新好友及金额封顶。
5. 可验证提前领取、助力截止后 72 小时截止、延迟回传不计入、活动整体结束不截断个人时限。
6. 可验证分钟弹窗间隔、首页常驻入口、结束后停止自动弹窗及分享链接保留注册入口。
7. 左右规则双向联动有效，规则无重复或缺失目标；PRD 与原型及已批准规则一致。
8. 现有不变功能置灰且鼠标、键盘均不能触发；新增修改功能可操作，关键视口无严重遮挡或溢出。
9. 实际打开页面检查核心流程、关键异常及控制台错误；修复后再交付，不能只做代码静态检查。

## 8. 不做范围

不制作签到、首单集代币、回归礼、多档红包、真实注册、真实分享发送、真实合作方任务、支付提现或后端服务。不改动 Kama 已有返佣与提现业务规则。
