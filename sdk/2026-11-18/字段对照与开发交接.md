# 测试后台字段对照与开发交接

核对日期：2026-11-18。基线为用户提供的测试后台；以实际查看的页面、应用拉活及客服建联两种表单为准。演示数据不代表线上数值。

本清单是 v4 原型完整性修正，不新增业务范围。**没有标记为删除的原字段与既有功能，开发均应保留。** 灰色或仅提供说明的既有操作，只表示原型不展开其旧流程，不代表生产环境禁用或移除。

**v4.1 用户指定例外：B 包广告数据移除“白包活跃人数”列，白包日活到对应“白包数据”查看；其余保留项不变。展示、点击、建联三个指标按参考图改成单层表头和斜杠合并数值，仅调整显示。**

原型为便于审阅拆分了部分设置分组；未明确要求调整的原布局、控件样式与字段排序继续沿用现有后台，不将演示分组理解为整页重做要求。

## 4. B 包编辑：按投放类型保留不同字段

共同保留：**关联应用、Logo上传、投放类型、投放标识、状态、取消、确定**。

| 类型 | 既有专有字段 | v4 调整 |
|---|---|---|
| 客服建联 | 投放名称；原提示国家在素材 | 保留投放名称；国家改到 B 包；添加 TG机器人 / 其他和两组跳转地址 |
| 应用拉活 | 包名、商店地址、国家 | 包名和商店地址完整保留；原 B 包国家继续保留为多选；统一跳转只配 1 个地址，不分 TG |

“商店地址”是原有字段，不能因为增加“统一跳转地址”而删掉或擅自合并。新 SDK 统一地址分配读取本次确认的跳转配置；商店地址其余旧用途不变。类型切换中不适用的表单隐藏而不是删除其他类型的旧数据。

国家选择继续使用生产后台原有完整字典。原型常用国家只是演示选项，不是缩减国家范围的需求。

## 5. 素材列表和编辑

保留：广告类型、素材上传 / 预览 / 删除、出价金额、状态、编辑、删除、新增广告及原校验。

迁移：素材独立跳转URL、独立国家配置改到所属 B 包。素材只读展示继承结果，可查看所属 B 包配置，不允许素材覆盖。除此之外不删字段。

**【本次更新 · v4.2】素材旧跳转 URL 仅删除编辑入口，不删除历史数据及旧接口读取字段。旧版历史素材继续返回原地址；旧版新素材的原字段由 B 包生成，新版对所有素材继续统一分配。详见第 8 节。

## 6. 报表保留字段与本次变更

### 白包自身明细（已确认的新入口）

按天保留新安装、日活跃；新增已安装TG、未安装TG、TG占比，**这三项分母为该行当天新增安装用户**，不是日活或累计用户。没有新安装时两组均 0，占比“—”。检测状态取最近一次打开 App；来源白包、日期范围及区间新增合计明确展示。

### B 包广告数据

共同保留原有：**事件关联B包、关联展示广告位（多选）、时/日/周/月入口、日期范围、更新、广告位列、人均展示次数、趋势曲线**。白包活跃人数按用户 v4.1 指令从 B 包报表移除；白包自身日活在白包数据中保留。

本次确认的新增指标按日演示；时 / 周 / 月入口和生产口径保留，原型不擅自新增跨周期新老用户规则。不得根据日报原型删除生产已有的其他粒度功能。

| 类型 | 原指标保留 | 本次变更 |
|---|---|---|
| 客服建联 | 展示、点击、人均展示次数、趋势曲线 | 单层表头：展示次数/展示人数、点击次数/点击人数、建联总/新/老；如 12/4、4/3、4/1/3；建联按安装日期判新老 |
| 应用拉活 | 安装、展示、点击、付费金额、付费人数（总/老/新）、人均展示次数、趋势曲线 | 展示和点击同样斜杠合并；建联为 —/—/—（不适用） |

展示人数、点击人数和建联人数按同一 B 包、同一自然日、同一 SDK 用户去重。当天安装当天建联是新，此前安装当天建联是老，包含老安装用户当天首次建联；总 = 新 + 老。点击与 `app_click_wa` 不等于成功建联。

**付费人数的新老继续沿用原有首次付费行为及统计周期规则，不把建联的新老分类自动套到付费。** 原有安装、金额和人均展示的生产计算不变。演示中人均展示仍用展示次数 / 原白包活跃分母，分母 0 显示“—”；隐藏 B 包报表列不要求删除该底层计算。各白包自身活跃单独在白包数据查看，不回写 B 包合计。

## 7. 交付边界与开发检查

- 原型只使用演示数据，不提交真实后台修改，不真实上报 Adjust。
- 原有字段名、接口字段、权限和校验以现有项目为准；本清单未要求更名的后端字段不得因页面文案改变而重建。
- 新增字段需要对应数据来源；原型数值不作为测试后台真实数值，也不代替事件上报和去重逻辑的集成测试。
- 开发对照本清单和 plan.md 实施：保留项不能因原型某个视口下需横向滚动或旧流程未展开而删除；迁移项不能在两个层级同时生效；删除项只限已列明的位置。


## 8. v4.2 旧版生产用户兼容与接口隔离【本次更新】

| 客户端 | 素材归属 | 跳转地址读取 / 返回方式 |
|---|---|---|
| 旧版 App / SDK | 本次升级前已有素材 | 保留原接口字段，继续返回该素材原有跳转地址 |
| 旧版 App / SDK | 本次升级后新建的客服建联素材 | 每次下发素材时，从所属 B 包“已安装 TG”组返回一条；TG 机器人和其他类型均适用，不读取未安装组 |
| 旧版 App / SDK | 本次升级后新建的应用拉活素材 | 每次下发素材时，返回所属 B 包唯一跳转地址 |
| 新版 App / SDK | 全部新旧素材 | 按新版流程在点击时请求 B 包统一地址；客服建联按最近 TG 状态分组，不使用素材旧地址 |

1. **历史数据保留**：升级前已有素材的原地址留在后台数据中供旧版读取；不批量覆盖、清空或从 B 包重新生成，不再提供修改入口。国家继承和其余素材规则仍按原计划，不因地址兼容恢复素材级国家。
2. **新素材兼容**：新素材不恢复独立地址输入框。旧版接口中原跳转地址字段由后台根据所属 B 包已保存配置生成；单条固定，多条每次下发重新随机，允许相同结果。
3. **空值处理**：新素材对应组或唯一地址为空时，素材仍下发，原字段返回旧版接口所兼容的空值，点击不跳转；不从未安装组或其他素材取兜底地址。不能因无地址过滤这条新素材。
4. **时机边界**：旧版可能复用已收到的素材，因此这里仅承诺每次下发重新取值，不承诺每次点击重新随机；新版每次点击请求分配不变。
5. **协议隔离**：新版 SDK 调用 v2 获取 B 包新配置并在点击时请求统一分配；旧版继续调用原接口读取素材字段，由接口版本明确处理分支，不再依赖猜测用户或 SDK 版本。TG 未上报不能作为协议路由依据。具体 URL、字段名和接口数量由开发确定，不在原型中伪造已存在的接口契约。
6. **素材边界**：历史 / 新素材按本次实际发布切换边界明确记录，不将本文日期 2026-11-18 硬编码成生产切换时刻；历史素材后续修改其他字段不应因此变为新素材或覆盖原地址。
7. **事件边界**：本次兼容不要求旧版自动补报新版 TG 检测或 app_click_wa，也不由后台伪造上报；保留旧版原有事件，新版事件条件按 5.4 执行。旧版未上报 TG 的用户在统计上仍归未安装，兼容跳转取“已安装 TG”地址组不代表将其统计状态改为已安装。
8. **上线核对**：实测旧版对空字符串 / 原接口空值的兼容处理，确认空地址不跳转且不崩溃。如果旧版本身不能满足，必须明确指出该技术限制，不能宣称仅后台改动即可保证。原型只模拟目标行为，不代替旧版真实安装包联调。

### 5.9 v2 与原接口隔离【本次更新】

| 通道 | 调用方 | 地址与返回行为 |
|---|---|---|
| 原接口 | 未升级旧版 App / SDK | 原响应字段及空值表示保持旧版兼容；历史素材取原地址，新素材在下发时按 5.8 生成兼容地址 |
| v2 接口 | 已接入新协议的新版 SDK | 获取 B 包新配置；客服建联在每次点击请求时由后台按最新 TG 分组返回一条，应用拉活固定唯一地址；历史及新素材规则一致 |

- 新配置获取和点击分配使用 v2 协议；具体拆成几个接口、实际 URL、HTTP 参数及错误码由开发结合现有工程确定。本 PRD 不将示意名称当作最终接口路径。
- v2 无地址或请求失败时静默结束，不自动回退原接口，不读取素材旧 URL，不从另一 TG 组取地址。后台不伪造旧版的 TG 检测或新版事件。
- 协议和响应处理分支隔离；B 包运营配置仍只有一套，不新增两套编辑入口或相互独立的运营配置副本。旧版新素材可读取同一套 B 包配置生成兼容字段，历史素材原地址仍单独保留。
- 原接口新增兼容处理时不能破坏旧响应结构或空值类型；v2 的新字段、TG 分组和分配逻辑不泄入原接口。新版调用 v2 不等于替历史安装用户强制升级 SDK。
- 联调应分别验证原接口和 v2，原型只明确协议通道与目标行为，不模拟已连接真实 v2 服务。

原型客户端能力、历史/新素材及空地址开关仅用于审阅，不要求正式后台增加人工分流开关；原地址不恢复编辑。
