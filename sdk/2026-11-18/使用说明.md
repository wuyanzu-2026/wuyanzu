# TG 安装统计与统一跳转分配 · v4.2 开发审阅原型

入口为同目录的 `index.html`。文件使用原生 HTML、CSS、JavaScript，无需安装依赖；复制时完整保留 `styles.css`、`app.js`、`reports.js`、`fidelity.js`、`compatibility.js`、`plan.md` 和 `字段对照与开发交接.md`。

交给开发前先看 `字段对照与开发交接.md`：已按测试后台核对白包、两类 B 包、素材和两类广告报表，分别标明保留、新增、迁移、删除。未标记删除的旧字段与功能必须保留。原型按审阅分组不等于要求生产整页重做；原有时/周/月及旧新增/删除流程保留，原型不展开的旧流程会明确提示，不表示生产禁用。

字段较多时可横向滚动；右上“放大原型”可暂时收起规则区，“显示规则”恢复双栏。点击规则标记会自动恢复规则区。这些均为审阅辅助，不要求正式后台新增。

## 建议审阅顺序

1. “白包 APP”列表已移除展示、点击，保留每个白包一行；查看累计安装、今日日活和 TG 分布。
2. 点击某行“白包数据”，查看该白包自身的新安装、日活跃，以及当天新增安装用户的已安装 TG / 未安装 TG / TG 安装占比。TG 两组之和等于当天新增，占比以当天新增为分母，状态取最近一次打开 App；零新增占比为“—”。默认演示日期 2026-11-11 至 2026-11-18，首尾均含，顶部保留区间新增安装合计。
3. 修改开始、结束日期后点击“查询”；“重置”恢复默认日期并查询。开始晚于结束或日期缺失时有校验。演示数据覆盖 2026-11-05 至 2026-11-18，其他日期可体验暂无记录状态；“问卷 Demo”展示真实零值的每日记录。
4. 明细页脚“审阅辅助 → 演示：下次查询失败”仅用于体验失败和重试，不属于正式后台业务字段。关闭明细返回列表；日期查询不会改变 TG 最新分布。
5. 进入“B包管理”，点击 B 包“编辑” → “国家与跳转”。国家支持搜索、多选、逐项移除及清空，未选即全球；地址仍按 v2 确认的规则配置。
6. “客服建联 · 演示 A”为“其他”类型，两组可多条；切换为“TG 机器人”会清空已安装组，只保留一个空框，未安装组保留。“客服建联 · 演示 B”为机器人类型，选择印度和孟加拉国；“应用拉活 · 演示”为全球，只有一个地址。
7. B 包“广告素材”显示继承的国家和统一跳转来源；素材不单独填写国家、地址。“查看 B 包配置”进入所属 B 包。
8. B 包“广告数据”按参考图使用单层表头：展示次数/展示人数、点击次数/点击人数、建联总/新/老；每格对应为如 12/4、4/3、4/1/3。B 包中去掉白包活跃人数列，请到对应白包数据查看日活。广告位多选、事件关联 B 包、人均展示及趋势区保留；应用拉活保留安装与付费字段，建联为 —/—/—。日期修改后点“更新”；原时/周/月入口继续保留。
9. 客服报表末尾可展开“审阅辅助：建联新老及去重演示记录”。对比安装日期、首次建联日期和当天重复次数，核对当天安装当天建联为新、此前安装当天首次建联仍是老；同 B 包同一天同一用户只计一人。辅助明细不是生产新增页面需求。
10. 右侧“分流演示”按 B 包已保存配置模拟点击，展示分配和 `app_click_wa` 条件；同一 B 包的不同来源白包共用地址。
11. 左侧 `R-xxx` 编号与右侧规则可双向定位。共 24 条规则；R-017 为新增用户 TG 分布，R-018 至 R-020 为 B 包日报与建联分类。宽表格可横向滚动，不能把视口外字段理解为删除。

所有数据均为演示数据。未展开的原有新增、删除等旧流程会提供“保留原逻辑”的提示，不表示正式环境禁用或删除。本原型不连接测试后台、不打开配置地址、不发送真实事件。修改仅保留在当前页面，刷新或点击“重置演示”即可恢复。

需求与验收见 `plan.md` 的 v4.1 展示修订；实际验证情况及直接打开方式的工具限制见 `verification.md`。v4 修订前的源码、文档与 80 项检查存放在 `verification/v4-before-reference/`。开发复用现有页面、接口与权限，原型代码不作为替换生产项目的实现。


## v4.2 旧版兼容审阅

1. B包管理底部“旧版跳转兼容” → “查看兼容演示”，或右侧“分流演示”选择旧版 SDK。
2. 选择历史素材，模拟下发返回只读历史地址；修改 B 包配置不会改写该地址。
3. 选择新素材：客服建联两种类型均读取已安装 TG 组，应用拉活读取唯一地址。每次点“模拟后台下发素材”取值；点“模拟点击已下发素材”不会重新随机。
4. 勾选“模拟对应 B 包地址为空”，仍显示素材已下发，原字段为空，点击不跳转。开关是审阅辅助，不是生产字段。
5. 新版分支保留原 TG 检测、点击分配和 app_click_wa 条件；旧版兼容不补报新版事件，也不改变其 TG 未上报归未安装的统计。
6. R-021 至 R-024 可双向定位；prd.html 已整合兼容矩阵、发布边界与真实旧版空值联调要求。无真实后台或 SDK 代码修改。


### v2 协议隔离补充

新版 SDK 通过 v2 获取新配置并在点击时请求 B 包分配；旧版继续调用原接口拿素材跳转字段。分流演示的客户端选项和结果日志明确标明协议通道，R-024 说明隔离边界。v2 无地址或失败不回退原接口。后台只维护一套 B 包运营配置。接口实际路径与契约由开发确定，原型没有真实请求 v2。
