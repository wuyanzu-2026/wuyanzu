白包 APP：列表与自身数据

3.1 列表

  • 保留状态、关键词、搜索和分页；每个白包一行。APP名称与包名各自独立列。
  • 保留 ID、Logo、关联投放、四广告位频次、累计安装、付费、建联、状态及既有操作。
  • 删除本列表展示、点击两列；原日活明确显示“今日日活”。
  • 新增“已安装 TG”“未安装 TG”“TG 安装占比”，统计当前白包累计安装用户的最新分布。
  • 原“广告数据”操作改为“白包数据”，进入当前白包自身明细。

3.2 TG 检测与累计口径

项目规则
已安装 TGAndroid 手机已安装 Telegram 即可，不判断账号登录
状态时点用户最近一次打开该 App 时的检测结果；后续打开可更新归组
未安装 TG明确未安装、历史从未上报、无法判断均计入
去重同一白包沿用现有安装用户身份；重复打开不新增安装人数
累计恒等式已安装人数 + 未安装人数 = 该白包安装用户总数
累计占比已安装人数 ÷ 该白包安装用户总数；总数为 0 显示“—”

3.3 白包数据明细

路径：白包 APP → 当前行“白包数据”。标题显示白包名称和包名。不得以关联 B 包的广告或安装转化数据替代白包自身数据。

字段 / 控件类型与范围规则
开始日期、结束日期日期，查询必填首尾均包含；开始不得晚于结束；沿用原近期范围，原型演示为 2026-11-11 至 2026-11-18，不硬编码为生产默认日期
查询、重置操作修改日期后查询；重置恢复默认范围并查询；关闭返回列表
区间新增安装非负人数所选范围每日新增之和，沿用 SDK 安装身份
日期平台自然日按天展示，多个日期分别成行
新安装人数非负整数此白包当天新增的安装用户

已安装 TG非负整数该行当天新增安装用户中，最新检测为已安装者
未安装 TG非负整数该行当天新增安装用户中，未安装或未知者
TG 安装占比百分比 / —该行已安装 TG ÷ 该行新安装人数；零新增时两组 0，占比 —

关键区别：列表 TG 基于累计安装用户；明细 TG 基于该行当天新安装用户。明细的分母不是日活、不是累计安装。

明细 TG 不是安装当天冻结快照。用户后续打开 App 的检测结果可以更新其所属安装日期的 TG 分布。日期查询不回放历史检测状态，也不更改列表累计统计。

日活只逐日展示，不以日均替代，不把每日人数之和称为跨日活跃总人数。同一用户使用不同白包时，分别进入各白包自身统计。

B 包：统一国家与跳转配置

4.1 入口与归属

沿用 B包管理 → 当前 B 包“编辑”。保留关联应用、Logo、投放类型、投放标识、状态等原字段；客服建联保留投放名称；应用拉活保留包名、商店地址。商店地址和新增统一跳转地址不是同一个字段，不合并或删掉。

同一 B 包下所有素材及所有关联白包共用这套配置；不同 B 包独立。白包编辑不维护跳转地址，素材不得覆盖。

4.4 编辑行为

  • “其他”切换为“TG 机器人”：立即清除当前编辑态所有已安装 TG 地址，仅保留 1 个空输入框；未安装组原内容保留。
  • “TG 机器人”切换为“其他”：保留当前内容，已安装组恢复允许添加多条。
  • 保存成功后生效；取消或关闭舍弃本次编辑，已保存内容不变；保存失败沿用原反馈并保留编辑内容供处理。
  • 地址组为空不阻止保存。没有地址不等于停用 B 包，点击处理按无地址规则执行。
  • 国家支持多选、移除及清空。保存后全部下属素材同步使用新范围；取消维持原范围。
  • 投放类型不适用的其他旧字段按现有逻辑隐藏和保留，不因界面切换擅自删除旧数据；以上 TG 地址类型清空规则是已明确的特例。

06 / REQUIREMENTS

Android 检测、分配与事件

本节描述新版 v2 链路；旧版原接口兼容见第 08 节。接口路径、请求字段和错误码由开发确定，原型不调用真实服务。

6.1 新版 SDK 主流程

  1. 用户打开白包 App，Android SDK 检测是否安装 Telegram，更新该安装用户最近状态。
  2. 用户点击素材，通过 v2 协议请求后台分配，依据素材所属 B 包读取已保存配置。
  3. 应用拉活直接取唯一地址；客服建联按已安装 / 未安装状态进入对应地址组，检测未知按未安装。
  4. 对应组无地址则静默结束；只有 1 条固定返回；多条由后台随机返回 1 条。
  5. SDK 拿到地址后发起跳转；符合 6.3 条件则在发起跳转时触发 Adjust 事件。

6.2 分配与异常

  • 每次点击素材并请求客服分配时重新随机，不按用户、会话或上次结果固定；允许连续两次随机到同一地址。
  • 客户端不从后台返回的多条地址自行抽选；后台只返回此次分配的一条。
  • 应用拉活无地址、客服对应组无地址、未拿到地址或分配请求失败导致无地址：App 不提示、不跳转，用户看到点击无反应，不上报 app_click_wa。
  • v2 不跨 TG 分组兜底，不回退原接口，不使用旧素材地址，不因上次成功而在本次未拿到地址时沿用旧分配。
  • 是否实际打开目标不作为此点击事件的等待条件；保持现有跳转机制，本次不新增目标可达性检测。

6.3 Adjust 条件矩阵

投放类型TG 状态拿到地址且发起跳转app_click_wa
客服建联未安装 / 未上报 / 无法判断是本次跳转触发 1 次
客服建联已安装是不触发
应用拉活任意是不触发
任意任意否不触发

事件名称 app_click_wa。对应事件 Key 在 App 内配置，后台不增加输入项。每次符合条件的点击跳转都触发，不按用户全局只报一次，不等待跳转成功。Adjust 投递、已有重试机制沿用当前实现，不在本次另造业务重试规则。

点击事件、地址分配、发起跳转及 app_click_wa 均不等于成功建联；真实建联事件的原触发条件继续保留。

8. v4.2 旧版生产用户兼容与接口隔离【本次更新】

客户端素材归属跳转地址读取 / 返回方式
旧版 App / SDK本次升级前已有素材保留原接口字段，继续返回该素材原有跳转地址
旧版 App / SDK本次升级后新建的客服建联素材每次下发素材时，从所属 B 包“已安装 TG”组返回一条；TG 机器人和其他类型均适用，不读取未安装组
旧版 App / SDK本次升级后新建的应用拉活素材每次下发素材时，返回所属 B 包唯一跳转地址
新版 App / SDK全部新旧素材按新版流程在点击时请求 B 包统一地址；客服建联按最近 TG 状态分组，不使用素材旧地址
  1. 历史数据保留：升级前已有素材的原地址留在后台数据中供旧版读取；不批量覆盖、清空或从 B 包重新生成，不再提供修改入口。国家继承和其余素材规则仍按原计划，不因地址兼容恢复素材级国家。
  2. 新素材兼容：新素材不恢复独立地址输入框。旧版接口中原跳转地址字段由后台根据所属 B 包已保存配置生成；单条固定，多条每次下发重新随机，允许相同结果。
  3. 空值处理：新素材对应组或唯一地址为空时，素材仍下发，原字段返回旧版接口所兼容的空值，点击不跳转；不从未安装组或其他素材取兜底地址。不能因无地址过滤这条新素材。
  4. 时机边界：旧版可能复用已收到的素材，因此这里仅承诺每次下发重新取值，不承诺每次点击重新随机；新版每次点击请求分配不变。
  5. 协议隔离：新版 SDK 调用 v2 获取 B 包新配置并在点击时请求统一分配；旧版继续调用原接口读取素材字段，由接口版本明确处理分支，不再依赖猜测用户或 SDK 版本。TG 未上报不能作为协议路由依据。具体 URL、字段名和接口数量由开发确定，不在原型中伪造已存在的接口契约。
  6. 素材边界：历史 / 新素材按本次实际发布切换边界明确记录，不将本文日期 2026-11-18 硬编码成生产切换时刻；历史素材后续修改其他字段不应因此变为新素材或覆盖原地址。
  7. 事件边界：本次兼容不要求旧版自动补报新版 TG 检测或 app_click_wa，也不由后台伪造上报；保留旧版原有事件，新版事件条件按 5.4 执行。旧版未上报 TG 的用户在统计上仍归未安装，兼容跳转取“已安装 TG”地址组不代表将其统计状态改为已安装。
  8. 上线核对：实测旧版对空字符串 / 原接口空值的兼容处理，确认空地址不跳转且不崩溃。如果旧版本身不能满足，必须明确指出该技术限制，不能宣称仅后台改动即可保证。原型只模拟目标行为，不代替旧版真实安装包联调。

5.9 v2 与原接口隔离【本次更新】

通道调用方地址与返回行为
原接口未升级旧版 App / SDK原响应字段及空值表示保持旧版兼容；历史素材取原地址，新素材在下发时按 5.8 生成兼容地址
v2 接口已接入新协议的新版 SDK获取 B 包新配置；客服建联在每次点击请求时由后台按最新 TG 分组返回一条，应用拉活固定唯一地址；历史及新素材规则一致
  • 新配置获取和点击分配使用 v2 协议；具体拆成几个接口、实际 URL、HTTP 参数及错误码由开发结合现有工程确定。本 PRD 不将示意名称当作最终接口路径。
  • v2 无地址或请求失败时静默结束，不自动回退原接口，不读取素材旧 URL，不从另一 TG 组取地址。后台不伪造旧版的 TG 检测或新版事件。
  • 协议和响应处理分支隔离；B 包运营配置仍只有一套，不新增两套编辑入口或相互独立的运营配置副本。旧版新素材可读取同一套 B 包配置生成兼容字段，历史素材原地址仍单独保留。

  • 联调应分别验证原接口和 v2，原型只明确协议通道与目标行为，不模拟已连接真实 v2 服务。

原型客户端能力、历史/新素材及空地址开关仅用于审阅，不要求正式后台增加人工分流开关；原地址不恢复编辑。
