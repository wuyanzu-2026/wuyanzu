2.1 展示与活跃

  • 分子：当前来源、白包、投放、广告位及时间范围内的有效展示事件数量；请求成功、加载成功、点击或激励完成不替代展示。
  • 分母：同时间桶内对应白包的活跃用户，复用现有稳定用户/设备标识及去重规则；广告位或来源筛选不能将分母缩成广告观看人数。
  • 白包入口的自建广告限定app_id和campaign_id交集；TopOn仅限定当前白包，不因没有自建投放关联而隐藏。
  • B包入口只展示当前自建投放，分母为所选对应白包范围的活跃用户；全部对应白包时按现有白包用户身份口径重算，不能混入无关白包。
  • 历史查询的对应白包范围依据历史归属事实，不只看当前有效关联；删除/解绑不能改写原事件的app_id、campaign_id。
  • 周/月/合计从同周期集合去重，不能将每日活跃相加或平均每日人均。人均值展示两位小数，计算保留精度。
  • 分母0时人均为null，界面显示“—”；展示0、分母>0则显示0.00；缺日志、未接入或查询失败为未就绪/错误，不能补零。
  • 同一展示只能属于TopOn或自建其中之一，按实际展示来源判定；自建失败回退TopOn后不能计成自建展示。

验算：同日白包100人活跃，其中20人看广告；自建300次、TopOn500次，则人均分别3.00与5.00。若三天活跃用户为100、100、100但区间去重160，自建展示共900，则区间人均5.625，显示5.63，不是3.00。

2.2 收益与消耗

  • 汇总键：UTC+0日期+稳定白包ID+国家代码。收益不按渠道复制。
  • 消耗记录唯一键：日期+白包ID+国家+渠道。同键重复应提示修改原记录，不默认新增一条。
  • 消耗、收益均为USD；安装数为人工录入买量安装数，与现有白包自然安装统计分开命名。
  • 收支差额=TopOn API收益−投放消耗。收益/消耗=API收益÷消耗×100%，不是净利润率。
  • 消耗缺失不同于手工填0。收益缺失、未完整或消耗未录入时，派生值显示“—”；消耗明确为0时可计算差额，但比值为“—”。
  • 日期范围合计用总收益和总消耗重新算比值，不能平均每日比值。有缺失/未完整组时汇总不显示完整差额或比值，可分别列出“已录入消耗”“已同步完整收益”及缺失组数。
  • 收益包括该白包相应日/地区的广告经营收入，不保证来自当日投放用户；不将此表包装成渠道归因ROI、LTV或队列回本报表。

验算：同日同白包同国家，Meta消耗60、Google Ads消耗40，API收益120，则消耗100、差额20、收益/消耗120%。两个渠道不能各计收益120。

3.2 服务端

  1. 7天内原客服仍启用时，按原粘性规则返回；移除会话占用判断，保持今日分配幂等。
  2. 普通新客先选启用、未达当日上限的普通客服；优先在班。
  3. 按今日分配数升序、最后分配时间升序，再沿用原并列规则。
  4. 没有候选时沿用放宽当日上限、兜底号和无人可分时提示/告警；删除放宽同时接待上限分支。
  5. 不能删除粘性记录、建联事实或历史分配来“释放会话”；遗留open_chats任何值均不参与分配。

实现时统一检查旧关闭会话路由、权限点和机器人管理命令，清理仅为该功能存在的调用；保留其他依赖历史记录的能力。数据库旧字段可先保留兼容，但业务逻辑停止读取，不要求本次立即破坏性删列。

四、广告选材：随机仅替换同价决胜

先沿用现有投放资格和请求上下文过滤，保留标识精确匹配、默认池逐位回退、地区、启用、关联、最低SDK等规则。每广告位独立处理，在同地区、同标识、同投放类型、同广告位的合格候选中保留价格优先；最高同价候选均有相同命中概率。

qualified = existingEligibilityAndCategoryFallback(request, slot)
pool = qualified candidates in the existing applicable competition scope
if pool is empty: keep existing no-ad behavior for this slot
else:
    maxPrice = max(pool.price)
    ties = pool where price == maxPrice
    winner = uniformRandom(ties)  // service-side on each selection
    return one existing slot object
  • 不通过打乱缓存一次后永远取首条实现；服务多实例及并发不得因相同固定种子永远偏向同素材。
  • 可使用均匀索引或等价的蓄水池抽样；抽样源可注入以做确定性测试，业务路径不保留创建时间/ID偏好。
  • 比价沿用原金额单位/精度，避免浮点误差把业务同价拆开。
  • 不新增按用户锁定、轮询、权重或强制次数均摊；不要求SDK每次show都联网。
  • 每位响应仍为单对象；省略标识只取默认池、非空标识优先自身并逐位回退默认池的既有兼容契约继续生效。

原型仅模拟同条件两条最高价素材抽样，无法验证真实候选加载、缓存失效或生产随机源。

五、白包与B包删除

5.1 数据与事务

  • 逻辑删除/归档，保留原稳定ID与必要名称快照，不能物理级联清掉历史事件、素材归属、安装、建联、付费和投放账目。
  • 事务内校验权限与对象、设置归档状态、解除有效关联；提交后通知缓存刷新。重复请求应幂等，不产生重复解除或错误统计。
  • 白包删除只影响该白包相关新下发；不连带删B包。B包删除只停止其广告参与新下发；不删白包及其他投放。
  • 将“当前可投放查询”和“历史归属查询”分开：历史回传不能只靠缓存中的有效素材/B包查归属。已删除对象的延迟事件仍应按历史事实处理。
  • 历史查询/报表保留已删除标识和原ID；当前管理列表与新增关联选项排除已删除对象。首版无恢复入口。
  • 缓存刷新失败需可重试，不能用物理删除历史关系代替刷新。SDK已有离线缓存按原生命周期失效。

5.2 交互

删除二次确认需显示对象名称、ID/包名、解除关联与停止新下发的影响。取消无变更；失败保持原列表；提交中防重复。只有具备删除操作权限的用户可提交，服务端也校验。

六、TopOn收益接入研究与落地约束

6.1 已查官方能力

官方综合报表使用POST /v2/fullreport，可查询API收益revenue；timezone支持0、8、-8。按渠道、流量分组等拆分时不提供实际API收益。首次使用须开通账号报表权限，按官方Publisher Key签名机制在服务端请求；上游广告平台报表授权也需完成。page_size最大1000，需处理分页。收益币种跟随开发者账号设置，并非无条件USD。

依据：TopOn Reporting API综合报表，核对日期2026-11-16。请求字段与错误码以联调时官方版本及账号权限为准。

6.2 拉取与发布

  1. 核对后台白包ID与TopOn应用ID映射，不按名称或包名模糊合并；同一原始收益不能映射到多个白包重复入账。
  2. 请求UTC+0，按日期、应用、国家获取；不按买量渠道分组拉取API收益。若同时请求广告位/广告平台细分，必须先对明细唯一键去重再汇总，不能混合层级重复相加。
  3. 使用revenue/API收益，保持revenue_estimate等预估字段独立；缺字段、null或错误响应不得转为0。
  4. 必须确认TopOn账号返回币种为USD。若实际币种不符，标记“币种不匹配”并阻止入本报表核算，不擅自汇率换算或改美元符号。
  5. 分页拉完并校验成功后再发布本轮完整分区；超时、限流、授权失败、任一页失败均保留上次有效值并标记失败/待完整。
  6. 按账号+UTC0日期+TopOn应用+国家+收益口径幂等覆盖；保留原始响应/批次信息便于对账，不能每次同步累加。
  7. 已过去日期也允许按上游修订覆盖。同步节奏、回看窗口、配额和数据到齐延迟由工程根据实际接口限制配置；不把某固定小时承诺为最终结算时间。
  8. 已取得部分当日收益可标记“待完整”，但不作为完整收益参与差额和比值；保留最近成功时间、最近尝试时间、错误原因。

6.3 上线前必须核验的事实

  • 账号授权、Publisher Key及签名、实际币种、所有广告平台报表授权。
  • TopOn应用映射、国家编码及未知地区数据归类；不得静默丢弃未知地区或映射失败数据来使总数看似完整。
  • TopOn选择UTC+0后的上游平台时区语义。有些数据可能沿用上游平台报表口径，须在口径说明中如实展示，不能声称接口已精确重切全部原始事件日界线。
  • 实际收益延迟及历史修订情况。API收益不是最终银行到账金额，不能作为财务最终结算承诺。

8.1 建议存储分层

  • 投放消耗：唯一维度、USD十进制金额、安装整数、操作人、版本/更新时间；修改写审计。
  • TopOn原始/分区收益：账号、源应用、日期、国家、timezone、currency、收益类型、数值、同步批次和完整性。
  • 应用映射：TopOn应用ID至稳定白包ID；保留历史映射事实，删除白包不物理清理。
  • 历史事件：稳定app_id/campaign_id/ad_id、实际source、事件标识和时间；归档查询不被当前有效关系过滤丢失。
  • 活跃统计：日/周/月及必要小时范围复用现有稳定标识，不以展示日志推算全白包活跃。

新增权限键由工程沿用现有操作授权方式配置，不新增角色类型。查看收益、填写消耗、同步配置分别授权；鉴权缺失/越权在服务端拒绝。
