## 1. 目标

完善白包广告位投放控制和注册事件回传配置，支持快速复制 B 包投放配置；将非机器人客服地址集中为客服组管理，并通过独立的 B 包广告数据页面按 TG 安装状态、当日安装维度查看投放效果及转化率。

## 2. 用户与场景

后台运营人员在电脑端管理白包 APP、B 包投放、客服地址及相关广告数据。操作权限沿用现有白包和 B 包管理权限，不新增角色或授权规则；TG 机器人继续在现有“Telegram 机器人”菜单维护。

## 3. 需求范围

本次范围包括：

1. 白包的开屏、Banner、插屏、激励四个广告位独立开关，并将开关状态返回 SDK。
2. B 包列表克隆：客服建联一键克隆，应用拉活填写新包名后克隆；本期不做批量克隆。
3. 白包注册事件接收地址及 Adjust 注册事件回传配置。
4. 新增“其他客服组”菜单，集中维护非机器人客服地址，并由服务端随机分配地址。
5. 客服建联投放在地址类型为 TG 机器人时，分别通过下拉框绑定已安装 TG 使用的机器人、未安装 TG 使用的其他客服组；迁移现有非机器人地址并保留 B 包绑定。
6. B 包广告数据由弹窗改为独立页面，增加 TG 状态、当日安装筛选及按人数计算的点击率、建联率。

暂不纳入：客服建联地区配置迁移、素材级客服机器人绑定、机器人列表展示绑定 B 包、建联广告素材优化、首页客服建联每日统计。国家配置不随客服地址管理迁移；本次不新增机器人维护页面。

## 4. 页面与核心流程

- 原型基准：以测试后台为参考，完整保留原有导航。实际只展开白包APP、B包管理、其他客服组和B包广告数据四个变更页面；变更页面内保留原有筛选、列表列、字段及操作。使用本地模拟数据。
- 未修改的数据概览、设备管理、Telegram机器人、经营收益、账户管理和角色管理仅保留低亮导航，不可点击进入，直达旧路由也回到白包APP。这只限定原型展示范围，不表示正式后台删除或禁用这些功能。
- 审阅方式：变更页面内现有功能降低亮度但保持可读、可操作；新增或调整内容提高亮度。相关现有弹窗可作为变更页面的操作上下文保留，不再绘制无改动的独立管理页面。
- 宽表保留原有全部列，可横向滚动、固定右侧操作并使用“全宽查看”。详情见 `后台功能对照.md`。

- 白包 APP 新增/编辑：设置四个广告位开关；查看注册事件接收地址并复制。
- B 包管理列表：对单条客服建联投放一键克隆；应用拉活投放先填写新包名，提交后克隆。两类副本均默认停用。
- 其他客服组：维护组名和客服地址列表，供 B 包绑定。
- B 包新增/编辑：投放类型为客服建联且地址类型为 TG 机器人时，“已安装 TG”选择一个现有机器人，“未安装 TG”选择一个其他客服组。
- 客服跳转：未安装 TG 的用户使用所绑定的其他客服组，由服务端从组内随机分配一个客服地址。
- B 包广告数据：从 B 包列表的“广告数据”入口进入该 B 包的独立数据页面，设置时间、TG 状态和安装维度后查看指标与趋势。
- 注册事件回传：将白包提供的接收地址填入 B 包的 Adjust 服务器回传地址；服务端收到事件后，使用关联白包现有的注册事件 Key 上报至对应 Adjust。

## 5. 功能与交互

### 白包广告位独立开关

- 开屏、Banner、插屏、激励分别显示和保存开关状态。
- 新增白包和现有白包的四个广告位默认开启。
- 关闭某个广告位后，该位置所有广告均不展示，包括自有广告与 Google 广告。
- 关闭开关不清除该位置已有的出广告次数和间隔配置；重新开启后继续沿用原配置。
- 开关状态随白包配置返回 SDK；保存后在 SDK 下次拉取配置时生效。

### B 包克隆

- 在 B 包列表提供单条克隆操作，本期不提供批量选择或批量克隆；每次操作只创建一个副本。
- 客服建联：点击克隆后直接创建副本。
- 应用拉活：点击克隆后弹窗填写新包名；包名必填、不得与现有应用拉活投放重复，校验通过后才创建副本。取消弹窗不创建副本。不因原投放停用而放宽包名唯一限制。
- 源码依据：现有应用拉活保存逻辑会拒绝重复包名，因此不能将包名原样复制，也不能把“副本”后缀当作真实新包名。[package.go](../web-ad/web/admin/package.go)
- 除应用拉活必须填写新包名外，复制原 B 包配置和广告素材；若原配置中存在客服机器人、其他客服组绑定关系，也一并复制。复制绑定关系不新建机器人或客服组；副本使用独立的投放、关联及素材记录，不因编辑副本而修改原投放。
- 副本默认停用，需用户检查后手动启用。
- 副本历史统计数据从零开始，不复制原包展示、点击、付费、建联等统计。
- 客服建联副本名称依次为“原名称-副本”“原名称-副本2”“原名称-副本3”等，查重包含已有启用及停用投放；名称由服务端分配，并发冲突时重新分配可用序号，不覆盖已有记录。
- 客服投放名称按当前字段上限 200 字符处理；添加完整后缀将超长时，截短原名称部分，为后缀预留长度。应用拉活副本以用户填写的新包名标识，不给真实包名追加“副本”后缀。[字段依据](../web-ad/pkg/entity/b_package.go)
- 请求处理中禁用当前克隆操作；应用拉活弹窗提交中禁用重复提交。同一次请求重试使用同一操作标识，不重复创建；用户在已知上次结果后再次主动克隆，才作为新的操作。
- 投放、白包关联、素材、机器人/客服组绑定必须完整成功或完整回滚，不留下半成品，不修改原投放。现有普通新增逻辑不能直接视为已经具备完整克隆事务。
- 成功提示“克隆成功，副本已停用”，刷新列表展示新副本。
- 明确失败且已回滚时，提示“克隆失败，未创建副本，请重试”；源投放不存在、无创建权限、包名冲突时，反馈对应原因。
- 网络超时或连接中断、创建结果未知时，提示“结果确认中”，按原操作标识核查结果；不得直接提示未创建，也不得自动创建第二个副本。核查后转为成功或明确失败反馈。
- 权限沿用现有新建投放及源记录访问权限，不能以克隆绕过新建权限。

### B 包注册事件接收地址（本轮原型暂不展示）

- 复用白包编辑页现有的“注册事件Key”，不新增鉴权 Key 字段。
- 每个白包提供一个固定注册事件接收地址，多个 B 包可共用该地址。
- 在白包编辑页展示接收地址，并提供一键复制。
- B 包侧将该地址配置为 Adjust 服务器回传地址。服务端接收注册事件后，使用关联白包的注册事件 Key 将事件上报至该白包对应的 Adjust。
- 注册事件 Key 为空时仍允许保存白包；此时接收事件无法完成对应的 Adjust 注册事件上报。
- 源码现状：已有白包注册上报由白包新设备入库触发，继续保留。MMP 目前仅有安装与付费入口，本次为 B 包注册新增专用回调入口，不能把 B 包注册回调配置到付费入口。
- 接收地址建议为 `GET <公开SDK接口基址>/v1/mmp/register_callback?app_id=<白包AppId>&package={app_name}&gaid={gps_adid}`，由固定白包 AppId 与环境接口基址生成模板。此为新增待确认方案，非现有可用接口。
- B 包归属可参考当前付费链路，按包名与 GAID 查询首次 B 包安装锁定的白包，并与模板内白包 AppId 核对；一条 B 包可关联多个白包，不能直接取关联列表第一项。具体异常、去重及重试建议见源码核查文档。
- 白包注册与 B 包注册分别触发、分别记录和处理。B 包注册只在自身回调链路内去重；白包注册记录不能拦截 B 包注册，B 包注册记录也不能拦截白包注册。

### 其他客服组管理

- 新增独立菜单“其他客服组”，用于维护非机器人客服跳转地址。
- 支持新增、编辑、删除客服组，维护组名与客服地址列表；每组至少保留一个客服地址。
- 用户需要跳转到该组时，由服务端从组内随机分配一个客服地址，不采用轮询或权重分配。
- 被 B 包引用的客服组禁止直接删除，提示先解除绑定；未被引用的组可删除。
- TG 机器人继续复用现有“Telegram 机器人”菜单，不在客服组菜单重复维护。

### 客服建联投放的跳转绑定

- 适用范围：B 包投放类型为“客服建联”，且地址类型为“TG 机器人”。
- 原“已安装 TG”输入框改为单选下拉框，选择并绑定一个现有 TG 机器人。
- 原“未安装 TG”输入框改为单选下拉框，选择并绑定一个其他客服组。
- 已安装 TG 的用户使用所绑定的机器人；未安装 TG 的用户使用所绑定的客服组，并由服务端随机分配组内客服地址。
- 上线时将现有 B 包已填写的非机器人客服地址自动迁移为客服组，保留原 B 包对应绑定，避免运营重新配置；原地址内容及对应关系不得丢失。
- 本次明确调整上述 TG 机器人地址类型下的两个绑定字段；其余地址类型不另行扩展交互。

### B 包广告数据独立页面与筛选

- B 包列表的“广告数据”入口由打开弹窗改为进入独立页面，明确展示当前 B 包，并支持返回 B 包列表。
- 保留现有时间范围、时/日/周/月切换、数据指标、明细与趋势展示，包括广告位、展示次数/人数、点击次数/人数、机器人分配次数/人数、建联总/新/老及人均展示次数等现有内容。
- 新增 TG 状态筛选：全部、已安装 TG、未安装 TG，默认全部。
- TG 状态以广告事件发生时记录的状态为准；用户后续安装或卸载 TG，不改变历史事件归类。
- 新增安装维度筛选：全部、当日安装、非当日安装，默认全部。
- “当日安装”指用户安装日期与所查看的统计日期相同。例如查看 2026-11-18 的数据时，当日安装指 2026-11-18 新安装的用户。
- TG 状态、安装维度可与时间条件组合使用；明细、指标和趋势均使用相同筛选条件。
- 日期沿用现有后台平台时间口径（印度时间 UTC+5:30），安装日期和统计日期采用同一口径。

### 历史数据兼容与新增事件记录

- 源码核查：本地 `ad_log` 和广告上报 DTO 没有事件 TG 状态、真实安装日期字段；设备表保留安装列表与首次入库时间，但不能据此断言每条广告事件的 TG 状态或真实安装日期。[广告日志](../web-ad/pkg/entity/ad_track_log.go)、[上报 DTO](../web-ad/pkg/dto/track.go)、[设备字段](../web-ad/pkg/entity/device.go)
- 历史数据缺失的 TG 状态或安装日期记为“未知”，分别保留缺失情况，不能默认归为“未安装 TG”或“非当日安装”。不新增“未知”筛选选项。
- 某维度选择“全部”时，保留该维度未知的历史数据；选择具体值时，只纳入该维度有可靠记录且符合条件的数据。其他筛选条件照常生效。
- 查询范围存在相关未知数据时，提示“部分历史数据缺少维度，筛选结果仅包含可识别数据”；不删除原始历史记录，不为了对齐总量强行分组。
- 只使用可信历史记录补齐可还原的维度；禁止用用户当前 TG 状态反推过去，禁止将设备首次入库日期直接当作真实安装日期。
- 新数据由 SDK 在广告事件发生时记录 TG 安装状态、当前展示广告的白包安装时间及事件时间，服务端保留相应事件快照；离线补报和重试保留最初的快照，不使用补报时状态或日期覆盖。
- “当日安装”按白包安装日与对应广告事件日比较，沿用平台时区；跨日期范围先按各事件对应日期判断，再进行时/日/周/月聚合，不一律与查询起始日比较。
- 本地 SDK 已发送广告事件 `timestamp`，后端当前广告上报 DTO 未接收该字段；本次需贯通接收与存储、补齐 TG 状态及白包安装时间。缺少新增字段的旧 SDK 事件按相应维度未知处理，不回填默认未安装或非当日安装。
- 建联等后续事件进行 TG 状态筛选时，应通过其关联广告/点击事件的历史快照保持同一筛选口径，不能改查用户当前设备状态；缺少关联快照时按未知规则处理。
- 明细、趋势、点击率和建联率均使用相同的筛选范围；某维度未知记录被筛选排除时，分子与分母同步采用相同口径。

### 点击率与建联率

- 在 B 包广告数据独立页面中新增点击率、建联率。
- 点击率＝点击人数 ÷ 展示人数，以百分比展示。
- 建联率＝建联人数 ÷ 点击人数，以百分比展示。
- 两项比率使用同一统计范围、同一组筛选条件下的人数重新计算，不使用次数口径，不对已有百分比求平均。
- 分母为零时显示“—”。

## 6. 规则

- 白包广告位开关状态与次数、间隔配置相互独立；关闭开关不改变次数和间隔。
- SDK 以其下次拉取到的白包配置为准应用广告位开关状态。
- B 包克隆仅复制配置，不复制历史统计；克隆生成的副本初始状态为停用。
- 克隆每次仅创建一个副本；客服建联直接克隆，应用拉活需提交不重复的新包名。完整复制失败则回滚；结果未知则先核查，同一次操作不重复创建。
- 客服组随机分配在服务端完成；B 包只保存对应组的绑定关系。
- 被 B 包引用的客服组不能直接删除，克隆副本的引用也属于有效绑定。
- 非机器人地址迁移须保留现有地址内容与 B 包对应关系，不改变原有投放关联。
- 数据筛选使用事件发生时的 TG 状态；当日安装按所查看的统计日期判断，不固定为查询操作当天。
- 点击率和建联率均按人数计算，并与页面其他数据使用相同的筛选条件。
- 历史维度未知不等于未安装 TG 或非当日安装；全部条件保留未知，具体维度筛选只统计已知且符合条件的数据。
- 注册事件回传按 B 包关联的白包确定目标注册事件 Key；一个白包的接收地址可供多个 B 包共用。
- 白包新设备注册与 B 包注册是独立业务事件，保留前者，新增后者，不相互替代、不共用事件去重记录。
- 注册回调的地址、鉴权、去重、重试及反馈已补充源码参考与建议，见源码核查文档；确认后再纳入正式验收。现有回调鉴权调用被注释，现有注册发送失败仅记日志，不能作为本次已具备的能力。

## 7. 验收标准

- 四种广告位可分别开启或关闭；新建及现有白包默认均为开启。
- 关闭任一广告位后，SDK 可获取该位置的关闭状态，且该位置不展示任何广告；其他广告位不受影响。
- 关闭并重新开启广告位后，原次数及间隔配置仍保留；保存的开关状态在 SDK 下次拉取配置后生效。
- B 包列表可对客服建联一键创建副本；应用拉活填写不重复的新包名后可克隆，空包名及重复包名不能提交成功。本期无批量克隆入口。
- 副本配置、素材及机器人/客服组绑定完整复制、默认停用、统计从零开始；应用拉活包名按本次输入，其余按复制规则处理；编辑副本不影响原投放。
- 客服建联副本名称按既定规则递增，包含停用投放的重名可避开；并发克隆不覆盖记录，超长名称保留完整后缀且总长不超过 200 字符。
- 连续点击和同一次请求重试不产生多份副本；任一复制步骤失败时完整回滚。明确失败与结果未知使用不同提示，结果未知时核查原操作而非另建副本。
- 白包编辑页展示固定注册事件接收地址并可一键复制；注册事件 Key 为空时仍可保存。
- 配置了接收地址的注册事件可按关联白包注册事件 Key 上报至对应 Adjust。
- 白包新设备注册上报继续正常工作；同一设备发生白包注册后，仍可正常处理其 B 包注册回调，两类事件不会相互被判为重复。
- 可在独立的“其他客服组”菜单新增、编辑和删除客服组；空地址列表不可保存，被 B 包引用的组不可直接删除。
- 客服建联且地址类型为 TG 机器人时，已安装 TG 可单选一个现有机器人，未安装 TG 可单选一个其他客服组；保存后保留对应绑定。
- 未安装 TG 的用户跳转时，由服务端在绑定组内随机分配一个客服地址。
- 现有非机器人地址可自动迁移为客服组，原地址内容和 B 包绑定不丢失，无须运营重新填写。
- 从 B 包列表点击“广告数据”进入该 B 包的独立页面，保留原有指标、时间范围、时/日/周/月和趋势功能。
- TG 状态与安装维度可分别筛选，也可组合筛选；明细、指标、趋势使用一致的条件。
- 用户后续改变 TG 安装状态，不改变历史数据归类；查看指定日期时，“当日安装”只筛选该统计日期新安装的用户。
- 点击率按点击人数/展示人数、建联率按建联人数/点击人数计算，筛选后同步重算，分母为零显示“—”。
- 缺失 TG 状态、安装日期的历史记录保留为未知；全部条件仍可查看，具体维度筛选排除对应未知记录，并出现历史维度缺失提示。未知不被计入未安装 TG 或非当日安装。
- 新 SDK 事件保留发生时的 TG 状态、白包安装时间与事件时间；跨日离线补报不改变原快照。旧 SDK 缺失字段时按未知处理；可信历史数据才允许补齐。
- TG 状态、安装维度筛选对明细、趋势及两项转化率一致生效，建联事件沿关联广告/点击快照应用条件。
