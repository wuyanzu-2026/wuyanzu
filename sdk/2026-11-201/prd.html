01 · 交付范围与独立上线

【本次更新】配置批与统计批分开开发、验收和上线

本目录仅交付白包广告位开关、B 包克隆、其他客服组及跳转绑定。配置原型保留原“广告数据”按钮，置灰不可点击；统计改版另批交付。统计页、维度筛选和转化率属于另一批，不得顺带纳入本批。

分类范围开发与验收边界
本批 · P0四个广告位独立开关后台保存并随配置返回 SDK；SDK 按开关控制对应位置的所有广告。
本批 · P0B 包单条克隆客服建联一键克隆；应用拉活填写不重复的新包名后克隆。副本停用、素材配置独立、统计清零。
本批 · P0其他客服组及 B 包绑定独立菜单维护地址；TG 机器人类型绑定机器人和客服组；其他类型的已安装 TG、未安装 TG 地址分别下拉绑定客服组；服务端随机分配，迁移原地址。
另批B 包广告数据统计独立数据页、TG/当日安装筛选、点击率、建联率及历史数据兼容不在本批。
暂缓B 包注册事件接收地址及专用回调不新增接收地址区块、复制入口或专用回调。历史核查资料不是本批接口需求。
保持现状现有统计与注册相关能力原注册事件Key、白包注册链路及现网旧统计功能保持现状；原型裁剪不要求删除现网功能。

两批的具体上线顺序和日期由排期确定，本 PRD 不预设日期，也不以统计批上线作为配置批的前置条件。与本批无关的现有页面，仅在原型中保留低亮导航。

02 · 页面与用户流程

目标用户为电脑端后台运营人员。解决现有广告位无法独立关闭、投放重复配置以及非机器人地址分散维护的问题。

白包配置

  1. 01进入白包APP列表并打开新增或编辑
  2. 02设置各广告位开关，检查原次数与间隔
  3. 03保存后台配置
  4. 04SDK 下次成功拉取后按保存状态执行

投放复制

  1. 01在 B包管理选择一条源投放
  2. 02客服建联直接克隆；应用拉活先填写新包名
  3. 03完整复制配置、素材和绑定，成功后显示停用副本
  4. 04运营检查后手动启用

客服地址管理

  1. 01在其他客服组新增组名与地址列表
  2. 02在客服建联投放选择地址类型
  3. 03TG 机器人类型绑定机器人与组；其他类型两个状态分别绑定客服组
  4. 04使用客服组的状态跳转时，由服务端随机分配对应组内地址

03 · CP-01 白包广告位独立开关

对象默认与保存SDK 展示行为
开屏 / Banner / 插屏 / 激励四个独立布尔开关；新增白包和存量白包默认开启。仅影响对应位置，其他位置不受影响。
关闭状态关闭不清空原新用户次数与间隔；恢复开启后沿用。该位置自有广告、Google 广告均不展示。
开启状态次数和间隔继续使用原字段、原校验及原逻辑。按现有出广告配置执行，本批不改变选材或频次算法。
生效时点后台保存成功不等于已触达所有设备。以 SDK 下次拉取到的白包配置为准，不承诺保存后即时生效。
  • 关闭状态在表单中仍可查看已保留数值；原型会暂禁该行数值编辑，但重新开启必须恢复原值。
  • 存量补字段或迁移后，缺省状态必须维持开启，不能把历史应用意外关停。
  • 开关在 SDK 侧必须覆盖该位置全部广告来源；仅停自有广告或仅改后台展示不算完成。
  • 原次数/间隔、安装及各 Adjust 事件配置、商店地址、Logo、应用状态均保持现有功能。
  • 配置拉取失败的恢复策略沿用现有 SDK；本批必须验证支持开关的 SDK 版本，不能把旧 SDK 未识别开关当作已生效。
对应原型规则

R-001～R-004。原型中的“SDK 生效预览 / 模拟 SDK 拉取”是审阅辅助，不是要求新增到正式后台的业务功能。

04 · CP-02 B 包单条克隆

触发与提交

源投放类型操作校验与结果
客服建联点击单条“克隆”直接提交。后端生成可用副本名；成功创建一个默认停用的副本。
应用拉活先弹窗填写新包名，再确认克隆。包名必填，不能与任何已有应用拉活投放重复，包含停用投放；取消不创建。
权限同时校验源投放访问权限与创建权限。指定投放账户不能借克隆绕过现有新建限制。
操作数量每次仅一条、一个副本。本批无批量勾选、批量克隆及批量限制配置。

复制边界

内容副本处理
投放配置复制投放类型、标识、关联白包、国家、地址及已有其他配置；应用拉活使用本次输入的新包名。
素材复制完整素材配置并生成独立记录；不得只因复用“查询启用素材”的旧方法而漏掉原配置。源/副本后续编辑互不影响。
图片/视频资源可以复用同一已上传资源文件；独立的是可编辑素材配置和所属记录，不要求无意义地重复上传文件。
机器人 / 客服组复制绑定关系，不重复创建机器人或客服组。两条投放引用同一组时，该组仍是共享对象。
状态与统计投放默认停用；不复制源包的安装、展示、点击、付费、建联等历史统计。
新标识副本使用新的投放与素材记录标识；不得通过旧包名或旧记录标识把源历史误算给副本。

名称与并发

  • 客服建联名称按“原名称-副本”“原名称-副本2”“原名称-副本3”递增分配。查重包含启用及停用记录。
  • 并发冲突由服务端重新分配可用名称，不覆盖已有记录。
  • 当前投放名称字段上限为 200 字符；超长时只截短原名称部分，为完整后缀留出长度。
  • 应用拉活副本以真实新包名标识，不给真实包名拼接“副本”作为替代。
  • 处理中禁用重复点击。同一次操作及其请求重试必须使用同一操作标识，不能另建副本。用户确认上次结果后重新主动克隆，才是新操作。

原子性与未知结果

  • 投放、白包关联、素材及绑定必须完整成功或完整回滚。任一步明确失败，不留下半成品、不改源投放。
  • 网络超时或断连不能直接判定未创建。显示“结果确认中”，核查原操作后再反馈成功或明确失败。
  • 现有普通新增代码不是完整克隆事务的证明；本批需专门验证事务、并发和重试防重。
对应原型规则

R-008～R-012、R-027。原型用模拟延迟、回滚和超时核查表达状态，真实事务与幂等需服务端实现。

05 · CP-03 其他客服组

对象字段 / 操作业务约束
客服组组名、客服地址列表组名非空；至少保留一个地址。地址备注/名称用于运营识别，不参与概率配置。
客服地址一个或多个 HTTP / HTTPS 地址非空且格式有效；本批不新增权重、轮询或地区路由配置。
新增 / 编辑保存整组配置失败保留表单供修正；成功后绑定该组的投放使用该组配置。
删除未引用时确认后删除被任意 B 包引用时禁止直接删除，包含停用投放和克隆副本，提示先解除全部绑定。
分配跳转时服务端随机选一个组内地址不能仅由前端随机；短期可能连续命中同一地址，不保证轮询顺序。
引用标识B 包保存客服组唯一标识不以组名是否唯一作为绑定依据；字段物理长度与数据库设计由技术评审落地。
  • 组内地址修改不会自动复制出多个组；原型中的分配预览只用来解释随机规则。
  • 不得因客户端重试或组的显示名称修改而丢失投放的绑定关系。
  • 无组可选时应显示空状态及维护提示，不默认绑定任意现有组。
对应原型规则

R-013～R-015。正式系统仍沿用现有角色与数据范围，不新增一套角色体系。

06 · CP-04 客服建联跳转绑定与迁移

适用条件：投放类型为“客服建联”。TG 机器人类型沿用下表前两项；其他类型按“其他地址类型”行分别绑定两个状态的客服组。

字段本批交互保存与执行
已安装 TG原输入改为单选下拉，选择一个已有机器人。保存机器人引用；用户进入所绑定机器人。机器人仍在现有菜单维护，本批不重做机器人后台。
未安装 TG原输入改为单选下拉，选择一个其他客服组。保存组引用；服务端从组内随机分配一个地址。
国家继续留在 B 包投放配置。不迁到客服组；不新增素材级国家配置。
其他地址类型已安装 TG 地址、未安装 TG 地址均改为客服组单选下拉框，可选相同或不同组。分别保存和回显两个状态的组引用；必选且校验有效性。服务端按 TG 状态在对应组内随机分配地址；克隆复制两处绑定，任一处引用均阻止删除该组。

两个列表展示绑定 B 包

  • 其他客服组列表与 Telegram 机器人列表仅展示绑定 B 包数量和查看绑定按钮；点击弹窗显示B包ID、名称、关联白包、状态与TG用途，无绑定显示空态。
  • 客服组汇总两个状态的引用；同一 B 包两处绑定同组仅计一次，同时展示已安装 TG、未安装 TG 用途。机器人仅统计客服建联 TG 机器人类型的有效引用。
  • 包含停用投放和克隆副本，保存变更或克隆后同步更新。Telegram 机器人列表纳入本批原型范围，原管理功能沿用。

已有配置兼容

  • 上线时将已有 B 包填写的非机器人客服地址迁移成客服组，保留 B 包原对应关系，不要求运营重新填写。
  • 其他类型原已安装 TG、未安装 TG 地址分别迁移，保留各自状态与组的对应关系，不得相互覆盖。原地址内容、应用关联、国家与其他投放配置不得丢失。迁移前后应能按原投放核对。
  • 迁移中不同投放、地址与组的映射策略由开发提供可核查清单，不能仅按显示名称随意合并。
  • 保存绑定时校验所选对象仍存在且在现有权限范围内；不能保存失效引用并静默绑定其他对象。
对应原型规则

R-016～R-018。R-006 仅说明原注册事件Key保留，不能据此增加新的 B 包注册回调。

07 · 字段与旧功能保留

字段类别类型 / 默认校验与边界
四个广告位开关4 个独立布尔值，默认 true逻辑字段必须覆盖四个位置；实际接口命名沿既有协议扩展，由开发确认。
原广告次数 / 间隔原整数字段与原默认值沿用原校验；关闭开关不改值，不把原型演示值 1、2 写成新业务默认。
应用拉活新包名字符串，确认前必填去除首尾空格后按现有包名校验和唯一规则检查，包含停用记录。

客服组名 / 地址字符串及非空地址列表名称必填，至少一个有效地址。未约定的新字段物理长度在技术评审中明确，不静默截断业务内容。
机器人 / 客服组绑定单一对象引用TG 机器人类型必须完成对应选择；其他类型两个状态均须选择有效客服组，不接受无效引用。
原注册事件Key原字段，允许为空不删除，不新增鉴权 Key，不把它当作本批新的接收地址或接口要求。

白包列表“怎么出广告”每条广告位说明左侧显示小号圆形状态图标：开启为绿色勾，关闭为红色叉。一行一个广告位，保留次数/间隔说明，删除上方独立状态卡片；按已保存开关状态展示，保存后同步更新。

原有页面上下文

  • 白包列表和 B 包列表各保留原有 15 列及既有筛选；不因原型画布窄而删列。
  • 白包编辑保留 Logo、AppId、TopOn、Adjust 配置、各事件Key、商店地址和状态。B 包编辑保留应用关联、Logo、类型、标识、包名/名称、商店与跳转地址、国家和状态。
  • 本配置原型完整保留原有广告数据按钮并置灰禁用，其他原有字段、列和操作也保留；未变动项置灰不可点击，新增/调整项高亮可点击。灰色不表示删除正式后台功能。
  • 原白包数据/TopOn与素材等相关旧弹窗作为上下文保留。未改动的其他页面仅保留低亮导航。
  • 演示场景、重置演示、全宽查看、规则联动和 SDK 预览是原型审阅工具，不是新增后台业务。

08 · 状态、反馈与权限

状态 / 场景面向运营的反馈开发处理
保存或克隆处理中保存中 / 处理中禁用重复提交；不丢失表单和源记录。
成功克隆克隆成功，副本已停用刷新并展示新副本，不能自动启用。
明确失败且已回滚克隆失败，未创建副本，请重试只在确认未创建时使用该文案。
创建结果未知结果确认中保留原操作标识，查原操作而非重复创建。
新包名冲突应用拉活包名已存在，请填写不同的新包名阻止提交，不按源是否停用放宽。
客服组仍被引用该客服组正在使用，请先解除绑定包含停用与克隆引用；可展示引用投放供定位。
必填 / 格式错误对应字段错误提示保持已填内容，不保存无效引用。
无创建权限沿用现有权限反馈前后端均校验；不能仅隐藏按钮后放开接口。
列表或下拉为空暂无数据 / 暂无可选对象不误绑默认数据；允许运营返回维护。

开发诊断日志与面向运营的文案分开。不要将数据库错误、密钥或内部响应原文直接展示给用户。

10 · 开发交付、核对项与文件

  • 后台前端：完整表单与旧字段保留，新增开关/绑定/客服组/克隆状态按本 PRD 实现。
  • 服务端：开关持久化与下发、完整克隆事务和判重、引用校验、随机分配、存量迁移与权限校验。
  • SDK：识别四位开关并真正阻断对应位置全部广告；端到端验证最低支持版本。
