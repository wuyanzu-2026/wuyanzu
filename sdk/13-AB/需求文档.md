# 白包广告数据统计补充需求

版本：V3.0 · 日期：2026-11-13 · 交付对象：前端、后端、测试

【本次更新】上午的独立投放统计已完成，本次交付仅保留「白包APP → 广告数据」的补充调整。原型已移除独立投放管理页面、入口切换和全量投放演示。本文件替代此前双入口需求，已完成内容不再列作本次开发任务。

## 1. 目标与页面范围

让运营在白包菜单查看其关联投放的付费人数或建联人数，复用已经上线的“总/老/新”统计口径。

- 白包列表沿用现网，直接展示白包安装用户、日活及原有概要指标；本次不修改列表统计口径。
- 从白包列表点击「广告数据」，弹窗仅展示当前白包关联投放的广告数据。
- 弹窗没有白包安装、日活或活跃人数，不增加白包自身数据区或其趋势。
- 本次原型只提供白包列表、白包广告数据弹窗、必要状态与规则说明。

## 2. 已确认的显示规则

| 选中关联投放类型 | 弹窗表格字段 | 人数显示 |
|---|---|---|
| 应用拉活 | 日期、广告位、B包安装、展示、点击、付费金额、付费人数（总/老/新） | 一个单元格，如5/3/2；不显示建联 |
| 客服建联 | 日期、广告位、展示、点击、建联人数（总/老/新） | 一个单元格，如5/3/2；不显示安装或付费 |

- 总/老/新固定顺序，一列展示，不拆成三列。
- 人数为非负整数，金额与人数分别展示。总人数=老人数+新人数。
- 数值不换行；大数可分别加千分位；空间不足时表格横向滚动，不截断数值。
- 原型示例：白包甲关联拉活投放人数5/3/2；切换客服投放后建联人数也是5/3/2。数据均为本地模拟。

## 4. 关联选择与查询范围

### 4.1 关联投放识别

- 保留现有「事件关联B包」下拉框。选项显示“投放名称 · 类型 #ID”，value使用稳定campaign_id。
- 应用拉活展示包名；客服无包名时按名称和ID识别，不能出现多个相同“白包名-”选项而无法区分。
- 不能以数组索引、包名、展示名称或投放标识替代稳定ID。同名、无包名或同标识均不合并。
- 默认选择首个有权限关联项，沿用既有排序；无关联则禁用下拉并显示“暂无关联投放”。

### 4.2 只看当前白包归属数据

查询条件为当前app_id、所选campaign_id、时间区间、广告位及当前账号授权范围的交集。选中包名后不能丢失app_id，也不能退回全部投放数据。

展示/点击沿用事件来源白包；付费沿用已锁定归因白包；建联沿用记录app_id。保持现有归因和回传规则。

切换白包后清除前一白包的广告数据；切换关联投放保留日期/粒度，广告位恢复该投放全部有效广告位，列、类型、范围说明和趋势同步刷新。

## 5. 复用现有总/老/新口径

这些规则是白包入口调用现有人数能力时的一致性约束，不是重新开发已完成的独立投放统计。

- 付费按用户在当前关联投放中的首次有效付费时间区分新老；建联按首次有效建联时间区分。
- 各关联投放独立判断首次；不按安装时间，不因白包入口、日期或广告位变化重置首次。
- 当前周期取当前白包归属且满足广告位筛选的有效事件，按稳定用户ID去重；同一用户多次事件/多个广告位只计1人。
- 首次事实查询覆盖该关联投放完整有效历史，不能先按当前白包或广告位缩窄再算首次。
- 每行时间区间[s,e)内首次行为为新；首次在s之前、当前行再次发生为老；新老互斥，总=老+新。
- 同周先新后再次发生，周内仍只计一名新用户。周/月从事件集合重新去重，不能累加日人数。
- 同一用户在其他白包中已发生首次、在当前白包再次发生时，当前白包报表计老。换了关联投放则独立判断。

平台时区沿用印度时间Asia/Kolkata（UTC+5:30）；日期首尾包含，服务端转换为结束日次日零点的左闭右开区间。自然周周一起算、自然月按月；小时跨日必须用完整日期+小时分桶。首次与周期归属使用同一时间源，沿用已上线统计时间，不单独迁移时间口径。

## 6. 交互与状态

| 状态/动作 | 页面表现与规则 |
|---|---|
| 正常进入 | 当前白包标题、关联投放、广告位、日期/粒度、对应类型表格与趋势 |
| 更新日期 | 完整且开始不晚于结束，点击更新生效；无效时提示并阻止查询 |
| 切换粒度/广告位 | 自动查询；至少保留一项广告位，全取消沿用现有恢复全部规则 |
| 加载 | 清除旧结果，显示加载提示，更新按钮禁用；关闭可用 |
| 零事件 | 有效时间桶展示0/0/0，不与失败混淆 |
| 人数未就绪 | 显示—及原因，不将缺失字段当零；金额按既有数据独立展示 |
| 无关联 | 弹窗仅提示“当前白包暂无关联投放”，不查询全局、不展示白包自身指标 |
| 请求失败 | 显示“数据加载失败，请重试”，保留条件，重试可恢复 |
| 无权限/关联解除 | 拒绝显示旧缓存，提示不可查看；不切到其他白包/投放 |
| 快速切换 | 仅最后请求生效，旧响应不得覆盖最新投放或白包 |
| 关闭 | 返回白包列表；白包列表既有安装用户/日活不受弹窗筛选影响 |

趋势保留现有广告指标开关；原型为方便演示一次显示一个指标。客服曲线使用去重建联总人数，与表格总数一致。不新增新/老三条曲线，不加入白包安装/活跃指标。

## 7. 开发对接要点

### 7.1 页面与接口

| 对象 | 本次要求 |
|---|---|
| 白包列表 | 继续使用既有列表接口与统计，不新增列表指标 |
| 白包详情组件 | 按所选关联投放真实类型确定列与人数展示，移除白包自身指标 |
| GET /dashboard/app-bpacks | 返回当前白包可查看关联项；需要campaign_id、campaign_type、campaign_name、package_name、ad_slots |
| 广告数据查询 | 同时带app_id、campaign_id、start_date、end_date、type、ad_type；服务端按真实关联与类型校验 |
| 现有人数能力 | 复用已上线数据服务；核验是否支持app_id子范围。若尚不支持，只补当前白包归属过滤，复用已有首次事实与去重口径 |
| 人数字段 | 复用现网已上线字段；前端取独立的总/老/新数值后拼为单格，不从金额/事件次数推算人数 |
| 返回范围 | 响应与请求的当前白包/关联ID匹配；按完整时间桶键对齐，不以短日期字符串匹配 |
| 失败 | 后端查询错误不可吞掉并伪装成功零值 |

本文件不指定新的独立投放统计接口字段名。开发核验已上线契约后直接复用，不重复实现已完成能力。

### 7.2 数据、权限与兼容性

- 稳定用户ID、历史首次覆盖和归属映射复用已上线实现；空用户ID、缺失首次或无法唯一归属的数据不得假装为精确人数，按现有质量处理反馈。
- 服务端校验白包查看权限、当前关联关系、投放授权范围三者交集；前端隐藏选项不能代替鉴权。
- 缓存含当前白包、关联投放、日期、粒度、广告位与授权范围；不能跨白包/账号复用结果。
- 页面接口不返回用户ID、Telegram ID或回调凭证等明细；原型账本仅为本地模拟核验工具。
- 共享组件修改需限制在白包入口，回归已有调用方以保证兼容，不将其列作本次新增功能。
- 不修改配置、SDK、竞价、频次、归因、金额及Adjust回传规则。响应时延与可查跨度沿用现有能力，发布前按实际数据量核验。
