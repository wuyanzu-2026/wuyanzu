# 客服广告建联

- 状态：最终需求 + 原型已对齐
- 版本：v9 / 需求 V1.4
- 更新日期：2026-10-27
- 变更说明：后台原型仍为 v9。需求 V1.4 钉死后端 6 条实现分叉（占用 click_id、HTTP 200、粘性计数、B7 告警、库失败、超级管理员配置），不改后台页面。

## 1. 目标

白包默认走 AdMob。开屏、Banner、激励各自按 N 插入自有广告。自有广告来自该白包已关联的全部投放，可以同时包含应用拉活和客服建联，按广告位命中后比出价。客服物料在 B 包管理中配置，按国家 + MCC 匹配，跳转到对应国家的 Telegram 机器人。机器人自己分配客服号。原型覆盖现有后台的看板、白包、B 包、设备、账户、角色。

## 2. 用户与场景

运营在现有 AdControl 桌面后台完成日常配置，并新增客服建联投放。同一白包也可以继续挂应用拉活。客服号加减、上下班不在本后台。

## 3. 需求范围

不新开顶级菜单。客服相关仍落在白包 APP 与 B 包管理。

- 登录 / 退出
- 数据概览：8 个指标卡 + 客服建联展示/点击/建联
- 白包 APP：三个 N、Adjust、注册/付费/首充/B包安装/建联事件Key。无自有广告类型
- B 包管理：投放类型应用拉活/客服建联，可同时关联同一白包
- 广告素材：客服跳转只填 t.me 机器人，国家和 MCC 可搜索勾选
- 设备沿用现网；账户沿用现网角色，并增加指定投放数据范围
- 广告数据：客服投放只看展示/点击/建联；白包同时看付费和建联

不做：真实广告请求；中台号池；WhatsApp；白包类型互斥。

## 4. 页面与核心流程

1. 登录后进入数据概览。
2. 编辑白包，填写三个 N 和全套 Adjust Key，不再选类型。
3. 在 B 包管理新增/编辑投放，选择应用拉活或客服建联，并关联白包。同一白包可两边都勾。
4. 客服素材填国家机器人 URL，国家和 MCC 配在素材上。
5. 广告数据沿用现有详情弹窗。

## 5. 规则

- N=0/1/5 含义不变，三广告位独立计数。
- 一个白包可同时出应用拉活和客服建联。
- 各广告位从所有已关联启用投放的命中素材里选出价最高者；未命中回退 AdMob。
- 客服跳转必须是 https://t.me/机器人用户名，不能带 start，不能填私人号或 WhatsApp。
- 建联=用户在机器人点击「立即联系」，不是点广告，也不是打开 Telegram。
- Adjust 配置始终留在白包。付费类事件和建联事件可以同时发生。
- 测试设备跳过定向和频次。
- 功能权限沿用现网角色；账户可指定全部投放或指定投放，子账户只看授权数据。

## 6. 验收标准

- 能走完现有后台主流程。
- 白包不能选类型，能配 N 和建联事件Key，没有客服素材按钮。
- A2test 同时关联 B2 和客服-东南亚时两边都是投放中。
- 客服素材只能保存 t.me 机器人链接。
- 建联文案不再写成「点击后拉起 WhatsApp/Telegram」。
